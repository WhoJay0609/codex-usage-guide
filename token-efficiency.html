    实用指南

    降低 Codex 任务的 GPT 消耗

    用更少上下文完成任务：收紧任务范围，再按需要调整并发、模型和工具输出。

    本文提供可复制的配置、安装步骤和 RTK 本机统计，帮助你从最常见的消耗来源开始优化。

    先选工具

    先分清消耗来自哪里#

    按当前瓶颈选择：重复说明用 AGENTS.md，独立工作用 Subagent，长命令输出用 RTK，冗长回答用 Caveman，实现范围用 Ponytail。

    分别看 Token、费用或额度、耗时。并行能缩短等待，但父线程和所有子线程的用量都要计入。

    方法输入与输出模型消耗影响可能省下的工作
    Subagent主线程分配独立子任务；子线程返回发现或改动。全部父子线程用量相加；适合缩短等待时间和隔离上下文。并行调查、审查或分工实现。
    配置设置子线程并发上限、默认模型和推理强度。模型和强度影响单次用量；并发上限只限制同时打开的子线程，不含主线程。控制并发，为简单任务选择合适模型。
    AGENTS.md保存跨任务会重复使用的规则。短规则减少重复输入；冗长规则会增加上下文。少重复说明项目入口、边界和命令。
    Caveman给回答启用简洁表达风格。减少回答长度；skill 说明会占少量输入。缩短状态、解释和汇报。
    Ponytail优先复用现有代码，只实现请求范围。少写无关代码，减少生成和审查。避免不必要的抽象和依赖。
    RTK压缩命令行输出后交给模型。缩短进入上下文的输出；rtk gain 估算命令输出变化。精简状态、测试和构建日志。

    建议顺序

    从低成本试起#

    1. 收窄上下文。写明目标、范围、相关文件和验收方式。
    2. 分配独立工作。用 Subagent 并行调查、审查或实现互不重叠的部分。
    3. 固定重复规则。把通用习惯放入全局 AGENTS.md，项目命令和边界放入仓库规则。
    4. 压缩长内容。Caveman 缩短回答，RTK 缩短命令输出；Ponytail 收紧实现范围。

    并发和模型

    配置代理并发和默认模型#

    Codex 默认启用 Subagent；直接提出子任务，或在适用的 AGENTS.md / skill 中要求使用即可。并行适合缩短等待时间和隔离上下文；所有子线程用量都计入任务总量。见 ↗（外部链接）OpenAI Subagents 文档。

    这个示例限制同时打开的子代理线程数为两个（不含主线程），并为子代理选择默认模型和推理强度。任务结束后关闭完成的子线程以释放名额。TOML 顶层键写在表之前，修改时保留现有设置。

    # ~/.codex/config.toml
tool_output_token_limit = 4000  # 可选：单项工具输出的历史预算，不是任务总 Token 上限
# model_reasoning_effort = "medium"  # 主线程可单独调整；先确认所选模型支持此级别

[agents]
enabled = true
max_concurrent_threads_per_session = 2
default_subagent_model = "gpt-6-luna"
default_subagent_reasoning_effort = "high"

    简单任务可改用较低推理强度或直接串行处理；按任务质量和总用量选择设置。模型名称与可用强度取决于客户端和账户。

    自定义角色

    在 .codex/agents/ 中配置角色#

    Custom agent 是一个独立 TOML 文件。项目角色放在仓库的 .codex/agents/，适用于当前项目；个人通用角色可放在 ~/.codex/agents/。用 name 调用角色，文件名和角色名保持一致，方便查找。

    • 必填：name、description、developer_instructions。
    • 可选：model、model_reasoning_effort、sandbox_mode。角色中的模型和推理强度覆盖继承或调用时的默认值。

    在项目根目录创建角色目录：

    mkdir -p .codex/agents
    ~/.codex/
├── AGENTS.md
├── config.toml
└── agents/
    ├── luna_worker.toml
    └── reviewer.toml

<repo>/
├── AGENTS.md
└── .codex/
    └── agents/
        ├── luna_worker.toml
        └── reviewer.toml
    # .codex/agents/luna_worker.toml
name = "luna_worker"
description = "按指定范围完成一个实现或文档任务"
developer_instructions = "遵守父任务给出的文件范围和验收标准；复用现有代码与文档；完成后运行指定验证并报告改动和结果。"
model = "gpt-6-luna"
model_reasoning_effort = "high"
    # .codex/agents/reviewer.toml
name = "reviewer"
description = "只读审查指定改动并报告可复现问题"
developer_instructions = "只读检查指定 diff；只报告有证据的问题，并提供文件路径、行号、影响和复现条件。"
model = "gpt-6-sol"
model_reasoning_effort = "high"
sandbox_mode = "read-only"
    1. 创建角色文件；每个文件定义一个角色。
    2. 新开任务，让 Codex 载入角色文件。
    3. 在请求中点名角色，并分配不重叠的工作。
    请让 luna_worker 只改 [明确文件]，按 [验收条件] 完成并运行 [验证命令]。
完成后让 reviewer 只读检查 luna_worker 的 diff，不要修改文件。
主线程负责检查整合后的 diff，并确认整体验收。

    config.toml 的 [agents] 设置共享默认值；角色文件指定某个角色的模型。AGENTS.md 说明团队约定和何时委派任务；角色的 description 帮 Codex 选择合适角色。创建角色文件本身不会启动代理。更多字段见 ↗（外部链接）OpenAI Subagents 文档。

    交给代理的任务

    把子任务说清楚#

    交给子代理四项信息即可：

    目标：[完成后的可观察结果]
范围：[必要上下文；可读或可改文件]
验收：[结果与验证方式]
返回：[结论、简短证据和未解决项]

    示例：

    请让 luna_worker 只读核对 tool_output_token_limit 的用途。
范围：OpenAI 官方配置参考页。
验收：说明它限制单项工具输出预算，还是整个任务的 Token 总量。
返回：来源链接、字段名和结论。

    只读调查写清可查范围；实现任务再补上唯一写入者和文件列表。主线程汇总简短证据并检查最终 diff。

    持久上下文

    精简 AGENTS.md#

    把跨项目习惯写进 ~/.codex/AGENTS.md，仓库规则写在项目根目录，局部规则放到相关子目录。Codex 从项目根目录向当前目录读取指令；更近一层补充细节或覆盖冲突项。项目指令默认上限为 32 KiB，所以常用规则写短，详细资料用按需读取的路径引用。见 ↗（外部链接）OpenAI AGENTS.md 文档。

    用户级示例：写适用于各仓库的工作习惯。

    # ~/.codex/AGENTS.md
## 通用工作方式
- 保留当前请求范围以外的工作。
- 报告改动文件和相关检查结果。
- 先查看相关文件，再执行本次任务。

    项目级示例：把占位文字替换成这个仓库的真实命令和文档路径。

    # <repo>/AGENTS.md
## 项目验证
- 快速检查：<替换为最窄的相关命令>
- 完整检查：<替换为项目验收命令>
## 按需读取
- 修改接口时先读 <仓库中实际存在的接口文档路径>。
## 角色分工
- 独立且范围明确的实现可交给 luna_worker；复杂改动完成后请 reviewer 检查。
## 编辑边界
- 页面正文由作者维护；导航和搜索索引由生成器维护。
- 保留与当前任务无关的工作区修改。

    全局规则写跨项目习惯，不放项目路径、命令或接口文档。项目规则写本仓库的验证命令、编辑边界和真实文档链接。

    简洁表达

    用 Caveman 缩短输出#

    Caveman 是简洁表达 skill。运行上游安装器并选择 Codex，再选 caveman：

    npx skills add JuliusBrussee/caveman -a codex -g

    在任务中调用 skill，并保留中文语法、条件、数字和代码：

    $caveman 请用简洁中文和完整短句回答，保留条件、数字、代码和必要的不确定性。

    Standalone skill 可用 $caveman；插件安装时使用列出的技能名。模式名会随版本变化，以安装后的 SKILL.md 为准。说 stop caveman 可结束当前风格；normal mode 可能同时关闭 Caveman 和 Ponytail。安装步骤见 ↗（外部链接）Caveman INSTALL.md。

    最小实现

    用 Ponytail 避免多写代码#

    Ponytail 帮助收紧实现范围：先复用现有 helper、标准库和平台能力，只补齐请求需要的代码。

    按上游方式安装插件：

    codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail

    用插件可输入 $ponytail:ponytail full；独立 skill 调用 $ponytail。说 stop ponytail 可结束当前模式。

    也可将上游 SKILL.md 放到 ~/.agents/skills/ponytail/SKILL.md，作为独立 skill 使用。安装和说明见 ↗（外部链接）Ponytail 上游仓库。

    命令输出

    用 RTK 压缩常见输出#

    RTK 压缩命令行输出。按系统选择一条上游安装命令；Cargo 方式需要 Rust 工具链：

    # macOS
brew install rtk

# Windows
winget install rtk-ai.rtk

# Linux with Rust toolchain
cargo install --git https://github.com/rtk-ai/rtk

    安装后确认版本，并预览初始化内容：

    rtk --version
rtk init --codex --dry-run

    检查预览后执行项目级初始化；需要应用到所有项目时加 -g：

    rtk init --codex
rtk --version
rtk gain

    初始化会写入 AGENTS.md 和 RTK.md；已有规则请合并保留。试用 rtk git status、rtk pytest -q 或 rtk npm run build。精确 diff 用 rtk proxy git diff。安装说明见 ↗（外部链接）RTK 安装文档。

    组合使用

    可复制的节省上下文提示词#

    把目标、范围、验收和验证写清楚，再按任务选择是否并行：

    目标：[一句话说明完成结果]
范围：[相关文件、必要背景、允许的改动]
验收：[完成条件]
只有独立任务才使用 Subagent；写明子任务和对应文件。
验证：[相关命令]
返回：[改动、结果、简短证据]

    比较方法

    如何做可信的前后比较#

    用同一仓库、任务、验收条件、模型和工具设置作比较，一次只改变一项。记录任务是否通过、返工次数和完成耗时。

    把父线程和所有子线程的输入、缓存输入、输出、推理 Token 与重试用量一并计入。若缓存输入已计入输入总量，或推理 Token 已计入输出总量，只算一次。分开记录冷缓存和暖缓存结果。
